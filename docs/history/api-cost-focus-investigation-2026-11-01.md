# 2026-11-01 API 费用焦点与原生补验调查

本记录对应本轮源码快照和独立验证范围，不把失败轮次中的部分图片视为整轮通过。

## 已保留的修正

- 费用场景经隔离焦点宿主交接后打开生产 NSPopover，要求窗口可见、应用活动且拥有键盘焦点。展开布局稳定时若发生瞬态关闭，先恢复可见焦点基线，再测量滚动。
- 逐项确认五个任务仍已展开、模型分项至少十二个，并记录顶部／中部／底部的实际偏移及窗口高度。验证入口拒绝缺失焦点、无溢出、未移动、缺少位置或高度变化的记录。
- 撤销夹具租约后先等待正常退出，再重新核对进程身份并保留强制清理兜底。新增回归证明能正常退出的夹具不需要发送信号。
- 增加焦点宿主激活策略、窗口可见性与 Space 状态诊断。未验证的普通预览激活策略试验已撤回。

## 当前阻断与后续验收

电脑使用工具最终明确返回：`The Mac is locked and automatic unlock could not unlock it.` 同期焦点宿主可见、允许成为键盘窗口、位于当前 Space，但激活请求返回 false。

因此需由用户手动解锁 Mac 并保持屏幕唤醒，再运行 `verify_local.py previews menu` 完成最终中英文全套预览和英文六种原生外观；视源码／产物变化决定是否补跑中文独立原生检查。当前不能宣称全套预览已通过。

原生检查证明 NSPopover、外观配置、程序化键盘交互及实际滚动。布局位图不单独证明 WindowServer 完整玻璃合成；硬件输入与 VoiceOver 人工验收不在上述通过结论中。
