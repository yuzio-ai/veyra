# 数据、隐私与兼容性

## 额度数据

Veyra 默认读取会话 JSONL 中的 `token_count.rate_limits`，按额度桶采用记录时间最新的完整快照。任务和额度共用日志游标；冷启动补读最近 20 个非内部会话（包含归档），每个最多尾读 256 KiB。每个额度桶保留自己的记录时间，缺失记录不会冒充完整账号额度。本地事件的 `limit_id` 只表示本次请求生效的限额，不区分模型家族（例如 Spark 任务也写作 `codex`），因此每条记录同时保留所属轮次的会话模型（取自 `turn_context`，缺失时退化为数据库中的线程模型）。

本地记录没有账号 ID，因此界面标注“本地快照”和记录时间，菜单栏用 `~` 标记。旧快照保留原始记录值；到达重置时间后仍等待新的真实记录，不自行推算为 100%。卡片外只显示需要处理的错误和警告，到期或缺失的重置时间显示在对应额度行中。

## 联网校准

只有用户点击“联网校准”时，Veyra 才启动独立的 `codex app-server --stdio`，读取 `account/read` 和 `account/rateLimits/read`，随后关闭子进程。联网结果保留完整额度列表；后续本地记录按会话模型与联网限额名称（如 `GPT-5.3-Codex-Spark` 对应 `gpt-5.3-codex-spark`）匹配归属到对应额度桶，再按各桶的记录时间更新对应卡片，匹配失败时退回事件中的 `limit_id`；未涉及的联网额度（例如已耗尽的主限额）继续保留。每张卡片分别标注来源和时间，同一额度桶内仍采用一份完整快照，不补回该快照中缺失的窗口。时间相同时优先采用联网结果，下一次成功联网校准会替换之前的联网列表。套餐信息独立保留至账号认证或配置变化，本地记录不会被赋予联网账号 ID。接口说明见 [Codex App Server 文档](https://learn.chatgpt.com/docs/app-server#auth-endpoints)。

重置次数来自同一响应中的 `rateLimitResetCredits.availableCount` 与 `credits`，仅聚合状态为 `available` 的条目，按 `expiresAt` 的 Unix 秒时间戳分组。本地日志不提供这份明细，因此重置卡片独立保留最近联网结果及校准时间，全部只缓存在内存中。网络失败保留旧结果，成功响应缺少字段则显示暂不可用；账号或配置变化会清空。已知批次到期后要求重新校准，不自行推算剩余总数，也不会自动联网或兑换重置次数。

手动请求的最短间隔为 60 秒。网络失败后分别等待 5、15、30 分钟，不自动重试；服务端提供更长的等待时间时遵守服务端时间。配置错误或未登录错误可在修正后重新操作。账号认证文件发生变化时，联网校准结果失效，本地记录仍保持账号归属未确认。

## 任务状态与用量

Veyra 只读访问 `state_*.sqlite`、`thread_history_*.sqlite` 和会话 JSONL，并结合 `lsof` 获取的任务锁或会话文件持有情况确认进程。只有未结束轮次且存在对应进程时才计入运行数；证据不足的记录显示为“状态待确认”。独立 App Server 的内存任务列表不用于判断桌面端或 CLI 的运行状态。

同一轮次的结束状态优先于开始状态，避免数据库秒级时间与日志毫秒级时间造成误判。不同轮次或缺少轮次 ID，且时间不足以可靠排序时，不推测开始时间，也不计入运行数。

累计 token 优先采用会话最新的 `total_token_usage` 快照，缺少快照时使用数据库累计总量。输入已经包含缓存输入，输出已经包含推理输出，因此不会重复相加。累计值包含该任务已完成轮次；子任务单独展示和计数，不叠加到父任务。

任务进展只读取带有明确轮次 ID 的公开 commentary 和工具名称，不读取继承对话、分派密文、推理过程或工具输出。摘要最多保留 2,000 字符，只缓存在内存中，不导出到诊断结果。

## 刷新与缓存

菜单打开或存在已确认运行任务时，Veyra 每 5 秒检查一次；菜单收起且没有已确认运行任务时，每 30 秒检查一次。打开菜单、手动刷新和系统唤醒会立即检查本地数据，休眠期间暂停调度。

只读 SQLite 连接和结果按数据库版本缓存，无变化的日志不会重复打开，但每次仍会采集新的进程证据。刷新任务列表时只发布实际发生变化的内容。

## 隐私与安全

Veyra 不创建、恢复或控制任务，不触发模型推理请求。账号认证和凭据刷新由 Codex 自身管理；应用不复制或存储 Codex 登录凭据，在自己的 UserDefaults 中保存路径等偏好设置。用户主动填写的第三方 API Key 仅存入本机系统钥匙串，不启用 iCloud 同步。实时任务和额度快照保存在内存中，退出后清除；任务统计的历史索引与模型方案另行保存在 Veyra 自己的目录。

模型配置是明确的写入入口：用户点击「设为默认」、菜单中的方案或撤销后，Veyra 通过 Codex 的 `config/read` 与 `config/batchWrite` 更新当前数据目录的用户级 `config.toml`，不编辑 Codex 数据库、会话文件或认证文件。每次写入使用读取时的版本校验；出现外部修改时不覆盖。切换不发起模型请求，不自动重启或控制聊天。

模型方案与恢复记录保存在 `~/Library/Application Support/Veyra/ModelProfiles/<数据目录哈希>/profiles.json`。目录权限为 `0700`，文件为 `0600`，使用原子替换。schema 2 方案只保存供应商、模型、地址、推理设置、可选上下文覆盖和不含密钥的钥匙串引用。旧 schema 1 连接保留在高级管理，不读取原环境变量值，不自动导入已有明文密钥或复杂 provider 认证内容。恢复记录仅包含所改字段的前后值，不备份整个 Codex 配置文件。请求中断后的待确认记录也保存在这里，用于下次读回核对；不会自动重试写入。替换 Key 时使用新引用，保留当前配置与撤销仍需要的旧 Key。移除被当前配置或恢复记录引用的 Key 会被阻止。

用户首次保存或替换供应商 Key 后，Veyra 发送一次模型列表 GET 请求；手动刷新也会发送请求。Key 仅用于认证请求头，不进入缓存。请求使用临时会话，禁用 Cookie、持久 HTTP 缓存和重定向，15 秒超时、2 MiB 响应上限，不自动重试。规范化模型列表、能力字段、上次成功时间和固定错误类别保存在相应数据目录哈希下的 `model-cache/`，按供应商、地址及凭据引用隔离。动态目录在启用时生成不可变文件，不覆盖撤销引用的旧目录；不导入供应商返回的提示词、审批策略或脚本。

Codex 通过配置中的 command-backed auth 调用签名 Veyra 的 `--provider-credential <引用ID>`，在不创建 NSApplication、不初始化监控与更新服务的模式中读取钥匙串。Key 只通过该子进程的 stdout 交给 Codex，不写入命令参数、环境变量、配置、普通 JSON 或诊断日志。GUI 退出后仍可取钥，应用被移动或卸载后需重新启用以修复路径。钥匙串拒绝访问或锁定时明确失败，不回退到明文。签名身份和真实钥匙串能力需要独立验收。

应用不会创建或迁移 Codex 数据库。错误界面和诊断输出舍弃后端原始错误文本与附加数据，只保留固定提示、结构化 HTTP 状态码、重试秒数和稳定错误分类，避免账号、路径或会话内容泄漏。

任务统计另行保存结构化历史索引：`~/Library/Application Support/Veyra/History/index.json`，文件权限为仅属主读写。索引保存任务标题、项目／源日志标识、父子关系、模型、执行起止时间、结果、用量和增量读取游标，不保存提示词、回复、推理、工具输出、凭据或未完成日志行的正文。不同 Codex 数据目录的记录分开保存和展示。源日志删除或截断后，已有历史可继续保留，并标明来源不可用；窗口中的“清除索引…”清除所有已保存历史后重新索引当前目录。

统计模块只读扫描已有数据库与 `sessions`、`archived_sessions` 日志，在独立后台服务中运行；窗口关闭时停止扫描。导出必须由用户手动选择位置，并可隐藏标题／标识和项目路径。导出文件不自动清理，也不会自动上传。

旧版 Codex 的标题字段可能包含首条消息全文。历史索引只保留首行、最多 240 个字符的标题标签，截断时显示省略号；多行消息内容不进入索引。

App Sandbox 保持关闭，以便只读访问用户选择的 Codex 数据目录和进程证据。用于手动公证发布的 App target 开启 Hardened Runtime；这两项配置互不冲突。

## 兼容性与限制

项目使用 Swift 6，部署目标为 macOS 14。当前实现已在 macOS 26.5.2、Codex CLI 0.152.0 和 Swift 6.3.3 上验证；macOS 14 仅完成部署配置和可用性编译检查，尚未在真机运行。

额度接口沿用当前 Codex 登录。API Key 不提供 ChatGPT 订阅额度的认证方式。任务列表和任务统计对应当前选择的本机 Codex 数据目录，不是跨设备的账号任务列表，不包含云端、其他设备或内部自动审批与维护任务。任务统计暂不包含 dsh 历史。

Codex 本地数据库和会话格式属于实现细节，Codex 升级后可能变化。读取器会检查已知列并兼容现有分页存储和旧 JSONL 格式；遇到不兼容格式时显示错误。默认查找数据目录根部最新编号的数据库，再查找其 `sqlite` 子目录；独立自定义的 `sqlite_home` 布局需要额外适配。

界面使用 [SwiftUI MenuBarExtra 窗口样式](https://developer.apple.com/documentation/swiftui/menubarextrastyle/window)。固定操作控件使用 [Apple Liquid Glass API](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)，并遵循 [Apple 关于固定玻璃操作层与滚动内容层的建议](https://developer.apple.com/forums/thread/791070)。

日常操作参见[使用指南](user-guide.zh-CN.md)，构建和验证参见[开发与手动发布](development.zh-CN.md)。
