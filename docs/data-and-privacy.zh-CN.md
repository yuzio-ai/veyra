# 数据、隐私与兼容性

## 额度数据

Veyra 通过本机独立的 `codex app-server --stdio`，读取 `account/read` 和 `account/rateLimits/read`，随后关闭子进程。额度、套餐和重置次数以接口返回为准，不使用会话日志补充额度，也不再为发现额度补读归档会话。各额度窗口显示剩余比例和重置时间；到达重置时间后不自行推算为 100%。

## 在线同步

启动时同步一次。有已确认运行任务时每分钟同步一次，空闲时每小时同步一次。任务状态变化会重新计算刷新时间；面板打开和普通任务刷新不会绕过间隔。睡眠时暂停，唤醒后检查是否到期。只有未配置 `openai_base_url` 的内置 OpenAI 路线显示 ChatGPT 额度；第三方供应商和自定义 OpenAI 网关隐藏额度并停止请求。切回官方路线后继续遵守原有冷却与服务端 Retry-After，等待到期后重新获取。供应商切换前发出的旧请求不能覆盖新额度状态，但同一数据目录下仍会记录其冷却和服务端等待时间；未返回的账号请求继续合并，避免往返切换重复请求。

用户也可手动刷新，已发起额度接口请求后的最短间隔为 60 秒；配置或登录前置检查失败时，允许修正后立即重试。自动与手动请求合并，同一时刻只发起一次有效请求。额度接口失败后分别等待 5、15、30 分钟；服务端要求更长等待时间时遵守该时间。自动重试同时受当前的分钟或小时间隔约束。启动、认证或配置前置检查失败仍按当前刷新频率重试，不进行高频重试。

重置次数来自同一响应中的 `rateLimitResetCredits.availableCount` 与 `credits`，仅聚合状态为 `available` 的条目，按 `expiresAt` 的 Unix 秒时间戳分组。额度与重置次数仅缓存在内存中。网络失败保留旧结果，成功响应缺少字段则显示暂不可用；账号、供应商或数据目录变化会清空。已知批次到期后要求重新同步，不自行推算剩余总数，也不兑换重置次数。

## 任务状态与用量

Veyra 只读访问 `state_*.sqlite`、`thread_history_*.sqlite` 和会话 JSONL，并结合 `lsof` 获取的任务锁或会话文件持有情况确认进程。只有未结束轮次且存在对应进程时才计入运行数；证据不足的记录显示为“状态待确认”。独立 App Server 的内存任务列表不用于判断桌面端或 CLI 的运行状态。

同一轮次的结束状态优先于开始状态，避免数据库秒级时间与日志毫秒级时间造成误判。不同轮次或缺少轮次 ID，且时间不足以可靠排序时，不推测开始时间，也不计入运行数。

累计 token 优先采用会话最新的 `total_token_usage` 快照，缺少快照时使用数据库累计总量。输入已经包含缓存输入，输出已经包含推理输出，因此不会重复相加。累计值包含该任务已完成轮次；子任务单独展示和计数，不叠加到父任务。

任务进展只读取带有明确轮次 ID 的公开 commentary 和工具名称，不读取继承对话、分派密文、推理过程或工具输出。摘要最多保留 2,000 字符，只缓存在内存中，不导出到诊断结果。

## 项目归属

项目分组只读使用 Codex 任务数据库中的 `cwd`、`project_id`、`projects` 和 `project_roots`。会话归属迁移完成前，兼容同一数据目录下 `.codex-global-state.json` 的项目定义、会话映射、无项目标记及迁移信息；只解析项目所需字段，不保留或输出其他桌面状态。归属迁移完成后停止使用旧会话映射。dsh 使用会话记录的 `record.identity.cwd` 作为目录推断依据。

没有明确归属时，先按路径组件匹配项目目录；再只读检查 `.git` 与 `commondir`，识别同一仓库的不同 worktree。不会启动 Git 子进程、读取 remote URL、修改仓库或根据目录名称猜测。项目和 Git 信息仅缓存在内存，Git 缓存最多保留 30 秒。桌面项目映射损坏时，桌面会话与子任务不按目录猜测归属；CLI、dsh 仍可使用其他可用项目目录独立推断。无法可靠识别时降级为“未归属项目”，不改变任务状态、运行数量或其他来源的监控结果。

## 刷新与缓存

菜单打开或存在已确认运行任务时，Veyra 每 5 秒检查一次；菜单收起且没有已确认运行任务时，每 30 秒检查一次。打开菜单、手动刷新和系统唤醒会立即检查本地数据，休眠期间暂停调度。

只读 SQLite 连接和结果按数据库版本缓存，无变化的日志不会重复打开，但每次仍会采集新的进程证据。刷新任务列表时只发布实际发生变化的内容。本地配置文件版本变化时，异步重读供应商配置以更新页头；配置不变的任务轮询不会重复调用配置接口。供应商忙碌、模型发现或连接测试进行中时合并等待最新重载，保留草稿、操作提示和编辑器选择，不写入 Codex 配置。读取失败按 5、15、30、60 秒退避重试；新请求或前台手动读取会取消旧等待。后台读取错误与用户操作反馈独立，恢复后清除读取错误。

## 隐私与安全

Veyra 不创建、恢复或控制任务，不自动触发模型推理请求。账号认证和凭据刷新由 Codex 自身管理；应用不复制或存储 Codex 登录凭据，在自己的 UserDefaults 中保存路径等偏好设置。用户主动填写的第三方 API Key 仅存入本机系统钥匙串，不启用 iCloud 同步。实时任务和额度快照保存在内存中，退出后清除；供应商连接另行保存在 Veyra 自己的目录。

模型配置是明确的写入入口：用户点击「应用」或「保存并应用」并完成必要确认，或在菜单中选择供应商时，Veyra 通过 Codex 的 `config/read` 与 `config/batchWrite` 更新当前数据目录的用户级 `config.toml`。勾选「设为 Codex 默认服务商」只表达应用意图；单独勾选或保存不会写入 Codex 配置。应用不编辑 Codex 数据库、会话文件或认证文件。每次写入使用读取时的版本校验；出现外部修改时不覆盖。仅保留未完成写入的恢复记录，成功后清除；旧版已完成的撤销记录不再使用。切换不发起模型推理请求，不自动重启或控制聊天。

供应商连接与恢复记录保存在 `~/Library/Application Support/Veyra/ModelProfiles/<数据目录哈希>/profiles.json`。目录权限为 `0700`，文件为 `0600`，使用原子替换。当前 schema 3 只序列化统一的 `connections`，包括连接身份、模型、地址、认证方式、不含密钥的钥匙串引用、能力覆盖及连接测试的固定分类和时间。兼容读取 schema 1/2，首次写回前保留旧 schema 备份；旧连接在统一侧栏中保留原有身份。恢复记录仅包含所改字段的前后值，不备份整个 Codex 配置。中断后的待确认记录用于下次读回核对，不自动重试写入。替换 Key 使用新引用，保留当前配置和恢复记录仍需要的旧 Key；移除被引用的 Key 会被阻止。

用户点击「刷新模型」时，Veyra 发送模型列表 GET 请求。单独保存或替换 Key 不自动获取模型。用户点击应用时，若内置供应商缺少匹配的模型列表，也会尝试获取，失败则停止切换。Key 仅用于认证请求头，不进入缓存。列表请求使用临时会话，禁用 Cookie、持久 HTTP 缓存和重定向，15 秒超时、2 MiB 响应上限，不自动重试。规范化模型列表、能力字段、上次成功时间和固定错误类别保存在相应数据目录哈希下的 `model-cache/`，按供应商、地址及凭据引用隔离。动态目录在应用配置时生成不可变文件，不覆盖恢复记录引用的旧目录，不导入供应商返回的提示词、审批策略或脚本。

用户点击「测试连接」时，Veyra 向所选服务的 `/responses` 发送一次 POST，输入固定为 `Reply OK.`，输出上限为 16 token，禁用流式传输并设置 `store: false`。此请求可能产生 API 费用，不携带本地文件或工具。测试使用临时会话，禁止重定向，30 秒超时、2 MiB 成功响应上限。只持久化连接范围、模型、协议、时间及固定失败分类，不保存响应正文。真实供应商调用需用户主动触发，自动测试只使用本地模拟服务。

Codex 通过配置中的 command-backed auth 调用签名 Veyra 的 `--provider-credential <引用ID>`，在不创建 NSApplication、不初始化监控与更新服务的模式中读取钥匙串。Key 只通过该子进程的 stdout 交给 Codex，不写入命令参数、环境变量、配置、普通 JSON 或诊断日志。GUI 退出后仍可取钥。移动应用后可通过详情中的凭据路径修复操作更新命令；卸载后取钥不可用。钥匙串拒绝访问或锁定时明确失败，不回退到明文。签名身份和真实钥匙串能力需要独立验收。

应用不会创建或迁移 Codex 数据库。错误界面和诊断输出舍弃后端原始错误文本与附加数据，只保留固定提示、结构化 HTTP 状态码、重试秒数和稳定错误分类，避免账号、路径或会话内容泄漏。

旧版 Dashboard 曾保存结构化历史索引：`~/Library/Application Support/Veyra/History/index.json`。Dashboard 已移除，当前版本不再创建、读取、更新或清除此索引。升级保留已有文件与用户此前导出的文件，不自动删除或上传。


App Sandbox 保持关闭，以便只读访问用户选择的 Codex 数据目录和进程证据。用于手动公证发布的 App target 开启 Hardened Runtime；这两项配置互不冲突。

## 兼容性与限制

项目使用 Swift 6，部署目标为 macOS 14。已有基础监控记录的环境为 macOS 26.5.2、Codex CLI 0.152.0 和 Swift 6.3.3；这是一份历史基线，不代表当前全部功能的验证范围。2026-10-28 的[Provider Settings V2 验证](provider-settings-v2-validation.md#最终验证)使用 Codex CLI 0.154.0，覆盖隔离配置接口及本地模拟服务下的签名取钥链路，不代表真实供应商 API 验收。各记录只对应其源码快照，后续修改需重新验证。macOS 14 仅完成部署配置和可用性编译检查，尚未在真机运行。

额度接口沿用当前 Codex 登录。API Key 不提供 ChatGPT 订阅额度的认证方式。Codex 任务列表对应当前选择的本机 Codex 数据目录，不是跨设备的账号任务列表，不包含云端、其他设备或内部自动审批与维护任务。dsh 任务由独立只读入口监控。

Codex 本地数据库和会话格式属于实现细节，Codex 升级后可能变化。读取器会检查已知列并兼容现有分页存储和旧 JSONL 格式；遇到不兼容格式时显示错误。默认查找数据目录根部最新编号的数据库，再查找其 `sqlite` 子目录；独立自定义的 `sqlite_home` 布局需要额外适配。

菜单栏由 AppKit 的 `NSStatusItem` 和 `NSPopover` 管理，弹窗内容由 SwiftUI 渲染。固定操作控件使用 [Apple Liquid Glass API](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)，并遵循 [Apple 关于固定玻璃操作层与滚动内容层的建议](https://developer.apple.com/forums/thread/791070)。

日常操作参见[使用指南](user-guide.zh-CN.md)，构建和验证参见[开发与手动发布](development.zh-CN.md)。
