# 能耗优化验收记录

日期：2026-09-03。环境：Apple M4 Pro、macOS 26.5.2。基线是修改前保留的 Release 应用，优化版使用本次工作的 Release 构建。

## 实现与回归

1. **本地额度优先**：独立解析 `token_count.rate_limits`，与任务共享增量游标。补读最近 20 个非内部会话，包含归档，每个冷读最多 256 KiB。每个桶保留最新整份记录、来源和记录时间；本地账号归属始终未确认。过期或跨重置时间显示等待更新，不自动恢复满额。
2. **手动联网校准**：取消后台额度循环，只有手动校准创建辅助进程，结束后关闭。并发请求合并，正常最短间隔 60 秒；网络失败等待 5、15、30 分钟，遵守更长的结构化重试时间。配置和未登录错误不进入网络退避。两种来源分别缓存，认证变化使联网结果失效；同一账号再次校准失败时保留已确认的快照。
3. **自适应调度与缓存**：菜单可见或有确认运行任务时每 5 秒检查，否则每 30 秒检查。休眠暂停，打开、手动刷新和唤醒立即读取；合并触发，不补跑错过的周期。只读 SQLite 连接按同连接 `data_version`、结构版本与文件身份缓存；历史使用分组最新轮次查询。每次仍重新检查进程和变更日志，任务列表与菜单文字按内容发布，隐藏时暂停界面计时。

`VEYRA_DERIVED_DATA_PATH=/tmp/veyra-energy-validation ./scripts/test.sh`：**167 项 XCTest、8 项独立应用诊断和 5 项语言检查全部通过**。最终 `./scripts/build.sh` 成功，保留 Swift 6、macOS 14 部署目标、arm64/x86_64 与无第三方依赖。

本记录是 2026-09-03 的验收快照，当时为 57 项 XCTest、7 项应用诊断；用例数会随功能增加而增长，最新数量以本文档上方命令的当次输出为准，后续日期有独立验收记录。

覆盖多桶和旧格式、缺失用量、乱序与半行、文件替换、尾读预算与缺失缓存、重置过期、来源和账号切换、手动合并与退避、辅助进程退出、调度切换和休眠、WAL 提交和查询竞争、结构变化与数据库替换、归档删除、数据库未变但进程退出或日志完成。后台、打开菜单、唤醒和普通刷新请求额度接口的次数在测试中均为 0。

## 工作量和本机诊断

- 空闲周期性进程检查从每小时约 720 次降为 120 次，减少 83.3%；这是 5 秒与 30 秒策略的换算，不包含启动、手动刷新、打开或唤醒触发。
- 缓存命中时任务、历史数据查询次数均为 0；未变日志读取字节数和打开次数均为 0，仍重新采集进程证据。
- 在本机真实 Codex 数据上运行默认只读 `--diagnose`：本地来源、3 个额度窗口、2 个运行任务；冷读约 0.461 秒，第二次约 0.030 秒。第二次的两类数据查询、日志字节数和打开次数均为 0，无任务警告。诊断未启用 `--network`，报告只保存统计，不保存账号或会话内容。

## 五分钟 CPU 对比

每次使用独立临时目录、1,000 条模拟会话；运行场景有 3 个持有真实锁文件句柄的模拟 Codex 任务，每 5 秒追加用量并提交数据库。脚本先通过目标应用的诊断确认运行任务数，再启动测量实例。旧版额度接口由本地假进程回应，不请求真实账号。

预热 10 秒后采样 300 秒。主进程 CPU 使用 `libproc`，按 `mach_timebase_info` 将 Mach 时间转换为秒。累计 CPU 使用进程退出后的 `wait4`，包含启动、预热和已回收的辅助进程，因此两个指标的时间范围不同。数值是 CPU 时间，不能换算为瓦数、实际电量或续航。部分独立场景在同一台机器上重叠采样；每种场景只做一次有效测量，未进行统计显著性判断。

| 场景 | 旧版主进程 CPU / 秒 | 优化版主进程 CPU / 秒 | 旧版累计 CPU / 秒 | 优化版累计 CPU / 秒 | 累计降幅 | 额度请求数：旧→新 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 空闲、收起 | 1.216 | 0.071 | 3.207 | 0.551 | 82.8% | 6 → 0 |
| 运行任务、收起 | 3.439 | 0.822 | 5.556 | 2.875 | 48.3% | 6 → 0 |
| 运行任务、面板可见 | 4.215 | 1.615 | 6.405 | 3.533 | 44.8% | 8 → 0 |

空闲累计 CPU 降低至少 60% 的目标已达到；运行任务收起及面板可见场景均未出现超过 10% 的 CPU 回退。面板测量使用同一内容的原生调试窗口，不能直接等同于 MenuBarExtra 弹窗的合成成本。最早未通过运行任务数核验的采样已排除，不计入此表。

复现命令见[开发与手动发布](development.zh-CN.md#能耗验证)。汇总数据见 [energy-measurements.json](energy-measurements.json)。

## 界面验收及限制

- 14 种固定场景 × 浅色、深色、两种高对比度，共 **56 张布局预览**通过尺寸预算检查。本地快照、过期提示、无记录和冷却均已检查。单任务 504pt，多额度 694pt；800pt 预览屏幕下溢出场景限高 776pt。
- 实际 MenuBarExtra 在浅色、深色、高对比度及不透明回退的专用测试实例中，顶部／中部／底部、快速滚动和同一窗口动态收缩检查通过；本地额度场景也已打开并取得布局位图。测试只操作专用模拟实例，没有修改系统外观或辅助功能设置。
- `screencapture` 对这些菜单窗口均返回 `could not create image from window`。布局位图不能呈现完整 WindowServer 玻璃合成；最终玻璃效果仍需人工目视确认，不标记为截图验收通过。
- 当前机器运行 macOS 26.5.2；macOS 14 仅验证部署配置和可用性编译检查，未在 macOS 14 实机运行。

构建、布局、真实菜单与诊断的原始输出保存在忽略的 `build/energy-*` 目录。未提交版本控制，也未替换用户正在运行的旧进程；重启 Veyra 后使用新的应用二进制。
