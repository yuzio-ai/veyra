## 选择与证据

本轮用户确认按讨论定稿并执行。采用 [D-r04](concept-D-r04.png) 的层级和身份布局，追加总量使用 K／M 缩写、精确值通过悬停及辅助功能读取的决定。

设计阶段使用 Vistra 0.1.3（产物契约 1），作者自检；该图为内置图像工具生成的静态概念图，不能证明原生材质、布局尺寸或交互验收通过。本次不改写原图中的完整总量，缩写决定以本文为准。

## 最终结构

1. 标题和运行状态；存在任务路径时，下一行以灰色等宽字体展示，单行中间截断并提供完整悬停文本。
2. 来源或“子代理：昵称”徽章、模型、耗时。过宽时耗时换到下一行右对齐，长徽章截断并保留完整悬停文本。无昵称时使用“子代理”。
3. 有进度时展示“最近进展／最近操作”小标题及最多两行正文，完整内容保留在悬停与辅助功能文本中。不添加嵌套卡片。
4. 一个用量折叠按钮：图标、任务范围标题、缩写总量、箭头。整行可点击；默认收起。标题、路径、身份、进度在收起时继续显示。
5. 展开后展示输入缓存占比及 4pt 细条，再展示缓存读取、未缓存输入、输出（推理）三项完整数字。

父子任务共用家族卡片，以逐层缩进和父子行之间的横向分隔线表达关系，不再绘制树状竖线。各任务使用自己的数据和展开状态，不新增家族用量总计；保留既有项目分组、父任务占位、状态待确认区域及滚动行为。

移除独立“来自”和“代理”行、重复输入总量、独立推理输出行、底部重复总量与辅助说明。既有角色字段存在时，在展开态保留为次级元信息。

## 数据与格式

- 未缓存输入仅在输入与缓存均有效且缓存不大于输入时计算为两者之差。
- 推理输出必须为输出的有效子集；显示为“输出（推理） 904,902（507,192）”，括号内使用次级颜色。加总时只使用括号外输出。
- 缓存占比继续使用原始缓存输入除以全部输入，保留一位小数；零输入和未知比例显示“—”及空底轨。
- 缺失或非法派生量显示“—”。未知缓存不会被推断为零。
- 总量沿用既有来源与解析规则；来源总量与完整、有效明细的合计不一致时不修改来源值，而在悬停中说明差异。
- 总量复用现有格式：小于千显示整数，K 一位小数，M／B 两位小数；436,424,881 → 436.42M，1,501,590 → 1.50M。
- 明细、悬停及辅助功能使用完整数字；辅助功能用“输出…，其中推理…”明确包含关系。

## 原生组件映射

沿用现有 360pt 面板、系统材质、20pt 卡片圆角、14pt 行内边距和层级缩进策略。标题 13pt，正文 11pt，路径／徽章 10pt，总量 14pt 中等字重。比例条使用系统蓝色，状态保留系统绿／橙；增加对比度时为底轨保留描边。

标题最多两行，进度最多两行。极长输出数值组合在数值区域内将括号部分换至第二行右对齐，不能撑宽面板。保持现有任务 ID 和辅助功能标识，不增加第三方依赖或持久化配置。

用量行采用“SwiftUI 标签 + 透明原生 NSButton”模式。SwiftUI 负责排版，原生按钮负责整行点击、焦点、Space／Return 键与完整辅助功能值；显示层从辅助功能树隐藏，避免重复朗读。折叠状态仍由现有按任务 ID 保存的 SwiftUI Binding 驱动。
